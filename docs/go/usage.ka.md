# ტერმინალში მუშაობა (`orcaton`)

[English](usage.md) · [Deutsch](usage.de.md) · [Русский](usage.ru.md) · **ქართული**

ბრძანება არის **`orcaton`** (ან `app-go/scripts/run.*` ინსტალაციის გარეშე). იგივეს აკეთებს ფანჯარაც
([docs/gui/user.ka.md](../gui/user.ka.md)) — ღილაკებისა და პარამეტრების შესაბამისობა იქვეა.

## სინქრონიზაცია
1. თქვენი მონტაჟის პროგრამა: ერთი კამერა ან რეკორდერი — ერთი ტრეკი; ტაიმლაინის ექსპორტი
   (*File → Export → Timeline…*) → **FCP 7 XML V5** (`.xml`) ან **DRT** (`.drt`).
2. გაშვება (ინსტალაციის შემდეგ **ახალ** ტერმინალის ფანჯარაში; მედია სხვაგან თუ დევს — `--map`, იხ. ქვემოთ):
   ```
   orcaton sync "Timeline 1.xml" "Timeline 1-out.xml" --report "Timeline 1-out.csv"
   orcaton sync "Timeline 1.drt" "Timeline 1-out.drt"          # DRT → DRT (ანგარიში თავისით იწერება)
   orcaton sync "Timeline 1.drt" "out.drt" --map "D:\media\project"   # მედია ახლა აქ არის (ძებნა სახელით)
   ```
3. თქვენი მონტაჟის პროგრამა: შედეგის იმპორტი (*File → Import → Timeline…*).

| კლიპის ნიშანი | რას ნიშნავს |
|---|---|
| ნიშნის გარეშე | სინქრონიზებულია **ხმით** (სიზუსტე — კადრი) |
| **Mango** | დაყენებულია **კამერის საათით** — ხმამ ვერ დაადასტურა (≈1 წმ) |
| **Rose** | წყვილი ვერ მოიძებნა — დგას გადაღების რიგით |

კამერის ფაილების რიგი განისაზღვრება სახელში არსებული ნომრით (MVI_0001, C0001, 00001…), შემდეგ — გადაღების დროით.
უწყვილო ფაილები დგანან თავისი კამერის ამ რიგით, მეზობლების გვერდით (სინქრონული მონაკვეთების შიგნითაც);
ფაილები, რომლებიც დისკზე არ არის, ყველაზე ბოლოში გადადის; ხვრელები არ რჩება. `.drt`-ში იცვლება მხოლოდ კლიპების პოზიციები, ხანგრძლივობა და
ტაიმლაინის სახელი; Rose/Mango ნიშნები `.drt`-ში ჯერ არ იწერება — სტატუსები `*_report.csv`-შია.

## `sync`-ის პარამეტრები
| პარამეტრი | ნაგულისხმევი | რისთვის |
|---|---|---|

| `--search საქაღალდე` | — | იგივეა, რაც `--map საქაღალდე`; შეიძლება განმეორება |
| `--search-depth N` | `6` | ქვესაქაღალდეების რამდენ დონეზე ეძებოს |
| `-y`, `--yes` | გამორთ. | ვერმოძებნილი ფაილების შესახებ არ ეკითხოს — პირდაპირ ტაიმლაინის ბოლოში |
| `--keep-paths` | გამორთ. | `--map`/`--search`-ით: წაიკითხოს ახალი ბილიკებით, შედეგში ჩაიწეროს ძველი |
| `--originals საქაღალდე` | — | ტაიმლაინზე პროქსებია: სად არის კამერების ორიგინალები (გადაღების დრო); შეიძლება განმეორება |
| `--unsynced` | `order_time` | `order_time` (კამერის რიგით, მონაკვეთების შიგნითაც) · `edges` (მონაკვეთის შიგნით არასოდეს; ბოლო მონაკვეთის შემდეგ — ბოლოში) · `end` · `remove` |
| `--max-gap` / `--keep-gap` | `0` / `0` | რომელი ხვრელები მოიხსნას და რა სიგრძემდე შემცირდეს, წმ |
| `--order-by` | `name` | კამერის ფაილების რიგი: `name` — ნომერი სახელში (MVI_0001, C0001, 00001…), შემდეგ გადაღების დრო · `time` — გადაღების დრო / TC, შემდეგ სახელი |
| `--singles` | `sequential` | უწყვილო ფაილები: `sequential` — ხმით უწყვილო სხვა ფაილებთან ერთდროულად არ მიდიან (დგანან თავისი კამერის მეზობლების გვერდით, საჭიროებისას დრო ემატება; სინქრონი არ იცვლება) · `stacked` — თითოეული თავისი კამერის რიგით, სხვადასხვა კამერა შეიძლება ერთდროულად მიდიოდეს |
| `--label` / `--time-label` | `Rose` / `Mango` | ნიშნების ფერები |
| `--min-conf` / `--min-ratio` | `12` / `1.5` | ხმით დამთხვევის სიმკაცრე |
| `--no-auto-threshold` | — | ზღურბლი პროექტის ხმაურამდე არ აიწიოს |
| `--min-overlap` / `--max-offset` | `2` / — | მინიმალური გადაფარვა და ძებნის ფანჯარა, წმ |
| `--audio-mode` | `mix` | `mix` · `first_stream` · `first_channel` |
| `--no-file-order` / `--intra-lane` / `--no-record-time` | — | კამერის რიგის გამორთვა / შედარება ტრეკის შიგნით / საათების არგამოყენება |
| `-j N` | `0` (ავტო) | რამდენი ფაილი დეკოდირდეს პარალელურად; ავტო — ბირთვების ნახევარი (2…16), HDD-ზე — 4-მდე |
| `--threads N` | `0` (ყველა ბირთვი) | კორელაციის ნაკადები — ნაკლები, თუ პარალელურად თქვენი მონტაჟის პროგრამა მუშაობს |
| `--mem-limit GB` | `0` (ავტო) | მეხსიერების ზღვარი: ავტო — ოპერატიულის ¾, 1-დან 7 GB-მდე; მინიმუმი 0,25 GB |
| `--cache საქაღალდე` | სისტემური | ნიშან-თვისებების ქეშის საქაღალდე |
| `--to xmeml\|drt` | გაფართოებით | გამოსავლის ფორმატი |
| `--config ფაილი` / `--no-config` | `orcaton.toml` | საკუთარი პარამეტრების ფაილი ტაიმლაინის გვერდით მდებარე `orcaton.toml`-ის ნაცვლად / პარამეტრების ფაილების არკითხვა ([ქვემოთ](#პარამეტრების-ფაილი-orcatontoml)) |
| `--brief` / `--json` | გამორთ. | შედეგი ერთ ხაზად / JSON-ად |
| `--progress auto\|text\|json\|none` | `auto` | პროგრესი stderr-ში: `auto` — ხაზად, მხოლოდ თუ stderr ტერმინალია და არ არის `--brief`/`--json`; `json` — ერთი მოვლენა ხაზზე (`stage`, `title`, `done`, `total`, `file` — იგივე ნაკადი, რასაც ფანჯარა იღებს, [api.ka.md](api.ka.md)) |

წყვილების კორელაცია პროცესორის ყველა ბირთვს იყენებს (შედეგი ბირთვების რაოდენობაზე არ არის დამოკიდებული).
მეხსიერება: პარალელური კორელაციები შეზღუდულია ზღვრით (`--mem-limit`), ხმის ნიშან-თვისება ითვლება
დეკოდირებისას — დაახლოებით 400 ფაილისა და 100 GB მედიის პროექტი ეტევა ~0,5 GB-ში. რა აირჩა და
რამდენი მეხსიერებაა დაკავებული — `Resources:` ხაზი `sync`-ის შედეგში (RAM → cap, threads, ffmpeg, დისკის
ტიპი, FFmpeg-ის ვერსია; პროცესის მეხსიერების პიკი). `orcaton version` — პროგრამისა და FFmpeg-ის ვერსია (ბილიკი; 4.4-ზე
ძველი — გაფრთხილება).

## პარამეტრების ფაილი `orcaton.toml`
`sync`-ის პარამეტრების ნაგულისხმევი მნიშვნელობები შეიძლება ფაილში ინახებოდეს — იგივე ფაილს კითხულობს ფანჯარაც
([docs/gui/user.ka.md](../gui/user.ka.md)). ფენები, ყოველი მომდევნო უფრო მნიშვნელოვანია:
1. ნაგულისხმევი მნიშვნელობები ზემოთ მოცემული ცხრილიდან;
2. **მომხმარებლის ფაილი** — ყველა პროექტისთვის: Windows `%AppData%\orcaton\orcaton.toml` · macOS
   `~/Library/Application Support/orcaton/orcaton.toml` · Linux `~/.config/orcaton/orcaton.toml`
   (`ORCATON_CONFIG` — საკუთარი ბილიკი, `none` — არ წაიკითხოს);
3. **`orcaton.toml` ტაიმლაინის გვერდით** (შემავალი `.xml`/`.drt`-ის საქაღალდეში) ან ფაილი `--config`-იდან;
4. ბრძანების სტრიქონის ფლაგი; `map`-ისთვის ცვლადი `ORCATON_PATH_MAP` ფაილზე მნიშვნელოვანია.
```
orcaton config "Timeline 1.drt"          # რომელი ფაილები იკითხება და რა მოქმედებს
orcaton config --init                    # მომხმარებლის ფაილის შაბლონი (ყველა გასაღები დაკომენტარებულია)
orcaton config "Timeline 1.drt" --init   # შაბლონი ტაიმლაინის გვერდით
```
```toml
[sync]
map = 'D:\media\project'        # Windows-ის ბილიკები — ერთ ბრჭყალებში
min-conf = 10.0
jobs = 4                        # HDD
originals = ['Sony', 'D:/Originals']   # ფარდობითი ბილიკები — ამ ფაილის საქაღალდიდან
```
* გასაღებები — `sync`-ის ფლაგების სახელებია `--`-ის გარეშე (`min_conf`-იც მუშაობს): `map`, `search`, `search-depth`,
  `keep-paths`, `originals`, `unsynced`, `order-by`, `singles`, `label`, `time-label`, `min-conf`, `min-ratio`,
  `auto-threshold`, `min-overlap`, `max-offset` (0 — შეუზღუდავი), `audio-mode`, `file-order`,
  `intra-lane`, `record-time`, `max-gap`, `keep-gap`, `jobs`, `threads`, `mem-limit` (GB), `cache`,
  `progress`. ფლაგები `--no-…` ფაილში არის `false` გასაღებისთვის `no-`-ს გარეშე (`record-time = false`). შესავალი, გამოსავალი და
  ანგარიში ყოველ გაშვებაზე განსხვავებულია და ფაილში არ შედის.
* გასაღების შეცდომა, არასწორი ტიპი ან დიაპაზონს გარეთ მნიშვნელობა — შეცდომაა ფაილისა და გასაღების სახელით, კოდი 2
  (ჩუმად „ნაგულისხმევზე“ არასოდეს გადადის). ფაილის სხვა სექციებს Orcaton არ კითხულობს და არ ეხება.
* `sync` ბეჭდავს ხაზს `Settings: <ფაილები>`, თუ რომელიმე ფაილი წაკითხულია.

## სხვა ბრძანებები
| ბრძანება | რას აკეთებს |
|---|---|
| `inspect FILE` | შეჯამება: სექვენციები, ტრეკები, FPS, ნიშნები, საქაღალდეები |
| `clips FILE [-t V1] [--csv OUT.csv]` | კლიპების სია (წამები და TC) |
| `convert IN OUT [--map …]` | XML ⇄ მოდელი ⇄ XML, DRT → XML, ბილიკების გადატანა |
| `cache [info\|clear\|prune] [--older-than 30d] [--dry-run] [--json]` | ნიშან-თვისებების ქეში (ქვებრძანების გარეშე — `info`) |
| `probe MEDIA`, `offset A B` | ფაილის მონაცემები; B ხმის წანაცვლება A-სთან შედარებით |
| `config [პროექტი] [--config ფაილი] [--init]` | პარამეტრების ფაილები `orcaton.toml` და მოქმედი მნიშვნელობები; `--init` — შაბლონი (არასოდეს გადაწერს) |

გასვლის კოდები: `0` — წარმატება; `1` — შესრულების შეცდომა (მაგალითად, შედეგი ვერ ჩაიწერა); `2` — შესავლის ან
პარამეტრების შეცდომა, მათ შორის `orcaton.toml`-ში (დიაპაზონს გარეთ რიცხვები — დიაპაზონი ჩანს `--help`-ში, მაგალითად `--jobs INTEGER [1<=x<=256]`);
`3` — FFmpeg ვერ მოიძებნა (მედიით სინქრონიზაციისას — დაუყოვნებლივ, ანალიზამდე); `130` — `sync` შეწყვეტილია
Ctrl+C-ით (ffmpeg-ის პროცესები სრულდება, გამოსავალი არ იწერება); `70` — პროგრამის შიდა შეცდომა (შეტყობინება და სტეკი გაუგზავნეთ დეველოპერს).

## მედია თავის ადგილზე არ არის
ტაიმლაინი ინახავს ფაილების სრულ ბილიკებს. თუ პროექტი სხვა კომპიუტერზე იყო მონტაჟდებული ან მედია
გადაიტანეს, მიუთითეთ საქაღალდე, სადაც ახლა დევს:
```
orcaton sync "Timeline 1.drt" "out.drt" --map "D:\media\project"
orcaton sync "Timeline 1.xml" "out.xml" --search "E:\Camera A" --search "F:\Sound"
```
* ფაილები ისხება **სახელით** (რეგისტრის გარეშე, NFC) ყველა ქვესაქაღალდეში `--search-depth`-მდე (6 —
  საკმარისია Sony-ის `PRIVATE/M4ROOT/CLIP`-ისთვის). თავის ადგილზე ნაპოვნ ფაილებს არ ეხება.
* ერთნაირი სახელები სხვადასხვა საქაღალდეში (`1/C0992.MP4` და `3/C0992.MP4`) გაირჩევა საწყისი ბილიკის

  ორივე ფორმის შერევა შეიძლება: `--map "D:/=G:/;E:\Sound"`.

  (შეგიძლიათ ფანჯარაში გადმოათრიოთ), **Enter** — გამოტოვება, `q` — გაუქმება. გამოტოვებული ფაილები დგება
  ტაიმლაინის ყველაზე ბოლოში ძველი ბილიკით — მონტაჟის პროგრამაში ისინი ოფლაინია და მოგვიანებით თავიდან უკავშირდება
  (*Relink Clips*). ტერმინალის გარეშე (სკრიპტი, `--yes`, `--brief`, `--json`) კითხვა არ არის — დაუყოვნებლივ გამოტოვებს,
  სია გაფრთხილებად გამოიტანება.
* XML-შედეგში იწერება ნაპოვნი ბილიკები (თქვენი მონტაჟის პროგრამა მედიას მაშინვე ხედავს; `--keep-paths` — ძველებს). `.drt`-ში

## ქეში
თითოეული ფაილის ხმის ნიშან-თვისება ერთხელ ითვლება და ქეშში ინახება: Windows
`%LOCALAPPDATA%\orcaton\cache` · macOS `~/Library/Caches/orcaton` · Linux `~/.cache/orcaton` (ან
`ORCATON_CACHE_DIR`, `--cache`). თუ სინქრონიზაცია შეწყდა, განმეორებისას მზა ნაწილი ქეშიდან იღება.
ბრძანებები ნებისმიერი საქაღალდიდან მუშაობს; იშლება მხოლოდ Orcaton-ის ქეშის ფაილები:
```
orcaton cache                         # სად არის ქეში და რამდენს იკავებს (= cache info)
orcaton cache clear                   # ყველაფრის გასუფთავება (ნიშან-თვისებები შემდეგ sync-ზე თავიდან გამოითვლება)
orcaton cache prune --older-than 30d  # მხოლოდ დიდი ხნის უსარგებლო და *.tmp ნარჩენები
```

## კითხვები და გადაწყვეტილებები
**DRT: სად არის Rose/Mango ნიშნები?** `.drt`-ში ჯერ არ იწერება — სტატუსები `*_report.csv`-შია. თუ ტაიმლაინზე
ნიშნები გჭირდებათ, აირჩიეთ გამოსავალი `.xml`.

**DRT XML-იდან?** შეუძლებელია: `.drt` იწერება საწყისი `.drt`-ის დაფატჩვით. ტაიმლაინი `.drt`-ად გააექსპორტეთ.
DRT → XML მუშაობს.

**მედია სხვა დისკზეა, შედეგი კი საწყის კომპიუტერზეა საჭირო.** `--map "D:/Project/=G:/Project/"`
(ან `--map საქაღალდე`) + `--keep-paths` — წაიკითხოს ახალი ბილიკებით, შედეგში ჩაწეროს ძველი.

**ტაიმლაინზე პროქსებია (ProRes თქვენი მონტაჟის პროგრამიდან).** პროქსებს გადაღების დრო არ აქვთ (მათი დრო რენდერის დროა) —
მიუთითეთ ორიგინალები: `--originals "G:\Sony_card"`. დროის გარეშე უწყვილო ფაილები უარესად დგება. გადაღების დრო
იღება ფაილის სახელიდანაც (`DJI_20261003231144_0085_D.MP4`; რეკორდერი `031026_191644_TrMic.WAV` — თარიღის
რიგი სხვა ფაილების მიხედვით ირჩევა) და რეკორდერის WAV-იდანაც (BWF).

**ფაილმა „წყვილი ვერ იპოვა“ (Rose).** მიზეზები: კამერას საერთო ხმა არ გაუგონია, სხვებთან გადაფარვა
2 წმ-ზე ნაკლებია, სიჩუმე. თუ ორიგინალები გაქვთ, `--originals` კამერის საათით დააყენებს (Mango).
ყოველი ფაილის მიზეზი ანგარიშშია.

**რამდენი ტრეკი შეიძლება?** შეზღუდვა არ არის; დრო ფაილების რაოდენობასთან ერთად იზრდება (ასობით — წუთები).
